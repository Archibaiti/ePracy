# План разработки `ePracy Private` (по этапам для Claude / GPT в Antigravity)

Этап разделён на независимые задачи, чтобы вы могли отдавать их разным моделям (**Claude** / **GPT**) с уже готовым фундаментом и экономить лимиты токенов.

---

## ✅ Этап 1: Разделение папок и Крипто-ядро (`vault_engine.js`) — ГОТОВО
- Старая корпоративная версия полностью изолирована в папке `Corporate/`.
- Новая версия находится в папке `Private_App/`.
- Создан и протестирован криптографический модуль `Private_App/src/vault_engine.js` (`window.VaultEngine`):
  - Сквозное шифрование `AES-256-GCM` в браузере (часы, ставки, заметки, настройки, данные для PDF шифруются до отправки в сеть).
  - Поддержка кнопки «Забыл пароль» + ручного сброса разработчиком **без потери зашифрованных данных** и без доступа разработчика к содержимому (`RSA-OAEP-256` конверт).
  - Готовый адаптер **Firebase Cloud Firestore** + встроенная локальная песочница `Local Sandbox` (можно тестировать весь сайт локально ещё до подключения Firebase).
- Настроен сборщик `Private_App/src/build.py` → собирает `Private_App/ePracy_Private.html` и батник `Private_App/Reset_Cache_Private.bat`.

---

## ✅ Этап 2: Самостоятельная регистрация, вход и «Забыл пароль» в пользовательском приложении — ГОТОВО
- Переведены [Private_App/src/index.html](index.html) и [Private_App/src/app.js](app.js) на `VaultEngine` (`AES-256-GCM`).
- Собрано автономное приложение `Private_App/ePracy_Private.html`.

## ✅ Этап 3: Компактная панель разработчика (`Private_App/Dev_Panel.html`) — ГОТОВО
- Создана автономная панель `Private_App/Dev_Panel.html` (из [dev_panel_template.html](src/dev_panel_template.html) и [build_dev.py](src/build_dev.py)).
- Реализованы: вход разработчика, фильтр запросов `🔔 Запросы на сброс пароля`, кнопки `🔑 Сбросить пароль`, `⛔ Блок`, `🗑️ Удалить` — без доступа к зашифрованным часам и личным данным.

> Ниже приведены исходные спецификации Этапов 2 и 3 для истории:
> **Кому лучше отдать:** **Claude** (или GPT) — чёткая задача по интеграции `VaultEngine` в уже готовый интерфейс `Private_App/src/index.html` и `Private_App/src/app.js`.

### Готовый промпт для отправки модели:
```text
Работаем ТОЛЬКО в папке c:\Users\Laptop\Desktop\Tablica\Private_App (папку Corporate НЕ трогай!).
Здесь уже есть криптографическое ядро `Private_App/src/vault_engine.js` (глобальный объект `window.VaultEngine`) и сборщик `Private_App/src/build.py`, который собирает `Private_App/ePracy_Private.html`.

Изучи API в `Private_App/src/vault_engine.js`, затем переведи `Private_App/src/index.html` и `Private_App/src/app.js` с Google Apps Script (`GAS_WEBAPP_URL` / `fetch`) на `window.VaultEngine`:

1. **Удалить старую серверную привязку:**
   - Убери `GAS_WEBAPP_URL` и старые вызовы `callGoogleAppsScript` к таблицам Google.
   - Вместо этого все чтения/сохранения смен, ставок, заметок, настроек (`userSettings`) и личного профиля PDF (`exportProfile`) храни в едином зашифрованном объекте `vault`:
     `{ years: { "2026": { year: 2026, baseRate: 34.40, months: [...] } }, activeYear: 2026, settings: {...}, exportProfile: {...} }`
     и сохраняй через `await VaultEngine.saveVault(vault)` (с мгновенным кешем на устройстве).
   - Подключи в `index.html` перед `app.js` `<script src="vault_engine.js"></script>` (сборщик `build.py` умеет встраивать его автоматически).
   - Также добавь возможность создать новый год прямо в шапке (`+` кнопка у переключателя лет, например 2027), чтобы пользователь сам управлял своими годами локально/в своём сейфе без админа.

2. **Новое окно согласия (прозрачность Zero-Knowledge):**
   - Польский язык по умолчанию (как в текущем `#disclaimerModalBackdrop`, без переключателя языка).
   - Обнови тексты 3 пунктов под приватную версию:
     1) Вспомогательный инструмент;
     2) Шифрование End-to-End AES-256: все данные шифруются в браузере ключом пользователя, даже владелец сервиса не имеет доступа к часам и личным данным;
     3) Профиль для PDF (ФИО, PESEL, счёт) также шифруется ключом пользователя и может безопасно синхронизироваться между его устройствами.

3. **Новое окно входа и самостоятельной регистрации (`#workerAuthModalBackdrop`):**
   - Сделай переключение между двумя вкладками: **«Zaloguj się» (Вход)** и **«Utwórz konto» (Регистрация)**.
   - На вкладке **Регистрация**: поля Login, Пароль (мин. 4 знака), Повтор пароля, Ставка bazowa (по умолчанию 34.40) -> вызывает `VaultEngine.registerAccount(login, pass, initialVault)`.
   - На вкладке **Вход**: поля Login и Пароль -> сначала проверяет `VaultEngine.checkAccount(login)`:
     - Если `status === "reset_pending"`, показывает экран **«Hasło zostało zresetowane — ustaw nowe hasło»** (Новое пароль + Повтор -> `VaultEngine.completePasswordReset(login, newPass)`), сохраняя все старые данные!
     - Если `status === "blocked"`, показывает сообщение о блокировке.
     - Иначе вызывает `VaultEngine.loginAccount(login, pass)`.
   - Добавь под формой входа заметную кнопку **«Zapomniałem hasła / Забыл пароль»**: при нажатии открывает шаг восстановления с полем Login и необязательным полем «Контакт / Примечание» (например, Telegram или имя для связи с разработчиком) -> вызывает `VaultEngine.requestPasswordReset(login, note)` и выводит понятное сообщение: «Заявка на сброс отправлена. Сообщите разработчику свой логин — после одобрения вы сможете задать новый пароль при следующем входе без потери данных».

4. **Переключение режима шифрованного профиля PDF:**
   - Так как в `Private_App` сейф зашифрован E2EE, можно синхронизировать `exportProfile` внутри `vault.exportProfile`, а при снятой галочке «Сохранять только на этом устройстве» — не записывать его даже в облачный сейф.

5. **Верификация:**
   - Запусти `python Private_App/src/build.py`.
   - Проверь через Playwright/браузер файл `Private_App/ePracy_Private.html?reset=1`: регистрация нового пользователя, ввод смены, кнопка «Забыл пароль», отсутствие JS-ошибок в консоли.
```

## 🛠️ Спецификация Этапа 3 (история промпта для `Private_App/Dev_Panel.html`)
> **Кому лучше отдать:** **GPT** (или Claude) — независимый автономный одностраничный HTML-файл с тёмным дизайном, полностью изолированный от пользовательского приложения.

### Готовый промпт для отправки модели:
```text
Работаем ТОЛЬКО в папке c:\Users\Laptop\Desktop\Tablica\Private_App (папку Corporate НЕ трогай!).
Изучи API разработчика в `Private_App/src/vault_engine.js` (`devNeedsSetup`, `devSetupPassword`, `devLogin`, `devIsLoggedIn`, `devLogout`, `devChangePassword`, `devListAccounts`, `devApprovePasswordReset`, `devSetAccountBlocked`, `devDeleteAccount`, `getModeLabel`).

Создай автономный одностраничный файл `Private_App/Dev_Panel.html` (весь CSS и JS внутри, шрифты Inter + JetBrains Mono, тёмная аккуратная тема, по умолчанию на русском/польском с переключателем RU/PL). Внутри HTML подключи код `vault_engine.js` (либо вставь его копию / сделай скрипт сборки `build_dev.py`, чтобы `Dev_Panel.html` работал автономно даже без локального сервера через `file://` и при этом легко обновлялся).

Требования к `Private_App/Dev_Panel.html`:
1. **Принцип Zero-Knowledge (НИКАКИХ данных пользователей):**
   - Панель НЕ имеет и НЕ должна иметь функций для расшифровки `encryptedVault`, просмотра графиков, смен, ставок или ФИО пользователей.
   - Показывает только техническую информацию об аккаунтах.

2. **Авторизация разработчика:**
   - При первом запуске проверяет `await VaultEngine.devNeedsSetup()`: если `true` — просит придумать пароль разработчика (`devSetupPassword`), если `false` — просит ввести пароль (`devLogin`).
   - Есть кнопка смены пароля разработчика (`devChangePassword`) и кнопка выхода (`devLogout`).

3. **Компактная панель управления аккаунтами:**
   - Индикатор вверху: текущий режим хранения (`VaultEngine.getModeLabel()`: Firebase Firestore или Local Sandbox).
   - 4 карточки счётчиков: Всего аккаунтов, Активных, Ожидают сброса пароля (`🔔 Запросы`), Заблокированных.
   - Поиск по логину + быстрый фильтр «Только запросы на сброс пароля».
   - Таблица аккаунтов со столбцами:
     - `Логин`
     - `Статус` (`Активен`, `🔔 Запрос сброса`, `⏳ Ожидает нового пароля`, `⛔ Заблокирован`)
     - `Дата создания` / `Последняя активность`
     - `Размер сейфа (КБ)` + отметка наличия заметки к сбросу (`resetNote`)
     - `Действия`:
       - **`🔑 Сбросить пароль`** (`devApprovePasswordReset(login)`) — подсвечивается ярко, если `resetRequested === true`. Переводит аккаунт в режим `reset_pending` без потери данных пользователя.
       - **`⛔ Блок / ✅ Разблок`** (`devSetAccountBlocked(login, ...)`).
       - **`🗑️ Удалить`** (`devDeleteAccount(login)` с окном подтверждения).
   - Поддержка `?reset=1` для быстрой очистки локального кэша.

4. **Верификация:**
   - Проверь в Playwright / браузере сценарий: первичный пароль разработчика -> вход -> отображение аккаунта из `localStorage` (`Local Sandbox`), одобрение сброса пароля, блокировка, удаление, 0 ошибок в консоли.
```

## ✅ Этап 4: Подключение бесплатного Firebase Firestore + Готовность к публикации — ГОТОВО
- Создан бесплатный проект в [Firebase Console](https://console.firebase.google.com/):
  - Project ID: `epracy-private`
  - Тариф: **Spark** (`$0/month`, без привязки банковской карты)
  - Зарегистрировано Web App: `ePracy Web`
  - База данных **Cloud Firestore** `(default)`: `Standard edition`, локация **`eur3` (Europe)**
- Опубликованы строгие правила безопасности из `Private_App/firestore.rules` (проверка схемы 13 полей `accounts/{accountId}`, защита `system_config/main` от удаления и сброса флага инициализации пароля разработчика).
- Ключи Web App прописаны в `FIREBASE_CONFIG` файла `Private_App/src/vault_engine.js`, пересобраны оба автономных HTML-файла:
  - `Private_App/ePracy_Private.html` — пользовательское приложение (пока что можно открывать прямо локально или залить на хостинг как `index.html`);
  - `Private_App/Dev_Panel.html` — ваша панель разработчика (держите только у себя, не публикуйте в открытый доступ).
- Сквозной живой тест с реальным Firebase Firestore пройден (`AES-256-GCM` шифрование в облако, дешифровка в новой сессии, «Забыл пароль», `Dev_Panel.html` видит облако `Firebase Firestore`).
- **Что дальше (по желанию):** опубликуйте `Private_App/ePracy_Private.html` под именем `index.html` на бесплатном статическом хостинге (**GitHub Pages** или **Cloudflare Pages**), чтобы раздавать одну удобную HTTPS-ссылку и обновлять приложение в один клик.
